# Huashu Design 执行清单（Sara Portfolio）

> 目标：使用 `huashu-design` 按顺序产出并合并 5 组改造方案，保持现有信息架构不变。

---

## 0. 执行前冻结（必须先做）

- [ ] 本地当前版本可运行（`npm run dev` 正常）
- [ ] 当前线上版本可访问（`http://182.92.151.116/` 正常）
- [ ] 明确不可变项：
  - [ ] 模块顺序不改（Hero/About/Projects/Blog/Bookmarks/Skills/Contact）
  - [ ] 路由结构不改（`/`、`/blog`、`/blog/:slug`、`/prompts/:slug`）
  - [ ] 现有内容资产不删（项目、博客、书签、联系方式）

---

## 1. 执行顺序（按此顺序，不跳步）

### Step 1 — Hero 专用人设版

**目标**：先统一首屏气质，定全站语调。  
**输入 Prompt**：Hero 专用人设版（已给）

验收通过后再进入 Step 2。

### Step 2 — 项目卡片交互重做

**目标**：强化项目区交互质感（磁吸、回弹、颗粒反馈）。  
**输入 Prompt**：项目卡片交互重做（标准版/重手版两套）

验收通过后再进入 Step 3。

### Step 3 — 博客系统体验升级

**目标**：打通首页预览 → `/blog` 列表 → `/blog/:slug` 详情的叙事体验。  
**输入 Prompt**：博客系统体验升级

验收通过后再进入 Step 4。

### Step 4 — 书签总览卡专属升级

**目标**：书签从“功能卡”升级为“作品封面卡”。  
**输入 Prompt**：书签总览卡专属升级

验收通过后再进入 Step 5。

### Step 5 — 首页视觉统一收敛

**目标**：统一 token / 间距 / 按钮语义 / 动效节奏。  
**输入 Prompt**：首页视觉升级（A/B/C 方向）

最终只保留 1 套落地方案。

---

## 2. 每步验收标准（统一门槛）

### A. 结构验收（硬性）

- [ ] 信息架构未变化
- [ ] 路由未破坏
- [ ] 关键入口仍可达（项目、博客、书签、提示词页、联系方式）

### B. 视觉验收（统一）

- [ ] 左右留白一致（推荐 `max-w-5xl` 作为统一基准）
- [ ] 同层级字号一致，无突兀放大
- [ ] 按钮语义清晰（查看代码 / 在线体验 / 查看提示词）

### C. 交互验收（体感）

- [ ] Hover 反馈明显但不眩晕
- [ ] 动画节奏统一（不卡顿、不抢主内容）
- [ ] 移动端无遮挡/误触/错位

### D. 构建与线上验收（发布前）

- [ ] `npm run build` 通过
- [ ] 关键页面 200：
  - [ ] `/`
  - [ ] `/blog`
  - [ ] `/blog/:slug`
  - [ ] `/cyberpunk-bookmarks.html`
  - [ ] `/prompts/:slug`

---

## 3. 合并策略（并回当前项目）

采用 **“模块化小步合并”**，不要一次性全量覆盖：

1. 每个 Step 单独产出（设计稿 / HTML demo / 参数说明）
2. 先抽取“可执行差异”（字号、间距、动效参数、token）
3. 仅改对应模块源码，不动其他模块
4. 本地验收通过后再并入主分支
5. 每一步都可回退（保留前一版）
